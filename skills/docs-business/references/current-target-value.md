# Current state, target state, and value

## Build the comparison as one model

Use the same vocabulary and comparable measures on both sides. A rename is
called out explicitly rather than silently changing the process or role name.

| Dimension       | Current state                                  | Target state                                      |
| --------------- | ---------------------------------------------- | ------------------------------------------------- |
| Outcome/process | how the relevant outcome works now             | how the same outcome should work                  |
| Roles           | who decides, performs, and receives the result | what responsibility changes or remains human      |
| Systems         | tools and workarounds actually used            | retained, integrated, replaced, or new capability |
| Measure         | sourced baseline, unit, period, and confidence | sourced/agreed target on the same basis           |
| Limits          | present constraints and failure points         | accepted exclusions and remaining constraints     |

Do not pad the comparison for symmetry. A genuinely new target capability may
have no current equivalent; label it as new. Keep screen steps and technical
mechanics on their functional or technical owner pages.

## Derive value from evidence

Every benefit connects a supported change to a beneficiary and a measure:

`current evidence -> target change -> beneficiary -> observable result`

Quantitative claims include baseline, target, unit, period, source, and the
assumptions behind the calculation. Qualitative claims still name observable
evidence such as fewer hand-offs, one auditable record, or a removed workaround.
Avoid empty phrases such as “greater efficiency” unless the next words identify
where and how it will be observed.

When supported inputs exist, show the calculation so the reader can challenge
the assumptions:

```text
annual value = (current effort - target effort) x unit value x annual volume
net annual value = annual value - recurring cost
payback period = one-time investment / net annual value
```

Label supplier estimates, benchmarks, customer estimates, and measurements
distinctly. State currency, tax basis, time horizon, adoption ramp, overlap
between benefits, and whether recurring cost is included. Never add benefits
together when they count the same saving twice. Pricing remains owned by the
pricing artifact; a business page links to its approved totals.

If any required input is missing, present the incomplete formula and the exact
decision or measurement needed. Do not substitute a “realistic” number.
