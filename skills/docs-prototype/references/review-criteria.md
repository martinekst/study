# Prototype review criteria

- The demonstrated journey and fidelity answer the stated decision or learning
  goal without expanding scope.
- Every behavior traces to current documentation or is visibly marked as a
  proposal.
- Required success, validation, empty, loading, permission, and failure states
  work for the selected journey.
- Keyboard navigation and critical accessible names work at the agreed fidelity.
- The handoff names build/run steps, supported paths, known gaps, and the
  documentation pages that remain authoritative.
- Prototype-only shortcuts cannot be mistaken for implemented behavior.
