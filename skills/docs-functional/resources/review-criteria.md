# Functional review criteria

- The opening explains the user/business outcome before detail.
- Shared actors, glossary, and cross-cutting rules have one canonical owner.
- Scenario pages contain one bounded actor goal with prerequisites, alternatives,
  result, and supported side effects.
- Process pages have a real E2E boundary, stages, roles, hand-offs, exceptions,
  result, and links to component scenarios/screens.
- UI pages own fields, actions, editability, validation, permissions, and visible
  states without duplicating process/scenario detail.
- Enabled views follow contract order and reciprocal links resolve.
- Discovery proposals, implementation-ready targets, and as-built evidence use
  the correct lifecycle semantics.
- No disabled view is generated and no “hybrid” duplicate catalogue exists.
