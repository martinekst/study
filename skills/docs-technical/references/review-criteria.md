# Technical review criteria

- The actual menu preserves established group paths and stable application codes;
  any structural change has an approved migration and repaired links.
- Folder/file prefixes are the only navigation order. Titles are number-free and
  page frontmatter does not contain an order field.
- Architecture boundaries and responsibilities are internally consistent.
- Lifecycle claims match their evidence; target and as-built states are separate.
- Interfaces include data, errors, auth, idempotency/versioning where applicable.
- Data ownership, retention/migration, and sensitive-data handling are explicit.
- Operational and security consequences are covered where relevant.
- Decisions and material unknowns are visible.
- Application indexes list only pages that exist, and every service code remains
  stable and unique.
- Concrete versions, identifiers, limits, thresholds, and operational procedures
  are sourced; placeholders are not presented as facts.
- The technical test overview distinguishes implemented suites/results from
  scenario-derived test design.
- Technical pages link to functional behavior, changes, and tests rather than
  duplicating them.
- Relative links and diagram anchors resolve; no index links to an omitted page.
- No empty catalogue pages or pure-tech portal behavior is fabricated.
