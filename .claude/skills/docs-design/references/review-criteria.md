# Design review criteria

- Visual decisions trace to a confirmed screen/interaction and user need.
- Tokens and components are reused instead of page-local reinvention.
- Empty, loading, error, success, disabled, and permission states are covered
  when the functional documentation supports them.
- Responsive and accessibility behavior is implementable.
- Design pages do not duplicate field/validation ownership from UI pages.
- Proposed values and current design-system values are clearly distinguished.
