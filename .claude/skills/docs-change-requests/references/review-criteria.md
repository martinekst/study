# Change-request review criteria

- Each group delivers one outcome and states exclusions.
- Dependencies, rollout/migration, reversibility, and failure behavior are clear.
- Acceptance covers the E2E business result, not only component completion.
- Tasks and design pages trace to the group and canonical documentation.
- Reciprocal links exist from affected scenarios/processes/screens/APIs/tests.
- State is supported by evidence and planned vs implemented is not mixed.
- The section is declared in README or the work is explicitly scoped as an
  extension pending an approved structural migration.
